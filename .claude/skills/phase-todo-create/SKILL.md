# phase-todo-create

## 목적

이 저장소는 문서를 다음 순서로 만든다: `README.md`(있다면) → `docs/constitution.md` → `docs/specification.md` → `docs/plan.md` → `docs/phaseN-todo.md`. 이 skill은 마지막 단계를 담당한다 — plan.md의 한 Phase를, **지금 코드베이스가 실제로 어디까지 되어 있는지**와 대조해서 바로 착수 가능한 체크리스트로 구체화하는 것이 역할이다.

다른 세 단계(constitution/specification/plan)와 달리 이 단계는 문서·대화만으로 완성되지 않는다. **실제 소스 코드를 읽어서 이미 된 것과 안 된 것을 구분하는 조사가 필수**다.

## 실행 순서

1. `docs/plan.md`를 읽는다. 없으면 "docs/plan.md가 없습니다. plan-create를 먼저 실행해주세요"라고 안내하고 중단한다.
2. 어느 Phase에 대한 todo인지 확인한다. 사용자가 이미 번호를 말했으면 그걸 쓰고, 아니면 "어느 Phase의 todo를 작성할까요?"라고 묻는다. plan.md에 없는 Phase 번호면 존재하는 Phase 목록을 보여주고 다시 묻는다.
3. plan.md에서 해당 Phase 섹션(작업 항목, 관련 FR/NFR/TR ID, 완료 기준)을 추출한다.
4. **선행 조건을 확인한다.**
   - 순차 진행 원칙(`plan.md`의 구현 원칙 참고)상 이전 Phase가 필요하면, 이전 `docs/phase{N-1}-todo.md`가 있는지, 그 문서의 "완료 후 확인사항"이 체크되어 있는지 확인한다.
   - 이전 Phase가 실제로 코드상 완료되지 않은 상태라면(아래 5번 조사로 드러남), 이 문서 상단에 그 사실과 영향 범위를 명시한다(예: "현재 payment 도메인은 모델만 존재하므로 이 문서의 N~M번 섹션은 착수 불가" 같은 실제 사례 패턴).
5. **코드베이스 현재 상태를 조사한다.** 해당 Phase가 다루는 도메인/영역의 실제 소스(`src/main/java/...`, 설정 파일, 관련 외부 저장소 등)를 읽어서 이미 구현된 항목과 아직 없는 항목을 구분한다. 이미 되어 있는 세부 작업은 처음부터 `[x]`로, 안 된 것은 `[ ]`로 표시한다 — 전부 빈 체크박스로 시작하지 않는다.
6. **관련 컨벤션 문서**(`.claude/rules/architecture.md`, `naming.md`, `patterns.md`, `infra.md` 등, Phase 성격에 맞는 것)를 참고해 plan.md의 큼직한 작업 항목을 실행 가능한 세부 단계로 쪼갠다.
7. **외부 시스템/저장소와의 계약이 걸린 Phase**(예: 프론트엔드 연동 검증)라면, 그 저장소나 설정 파일을 실제로 조사해서 발견한 사실(환경변수, API 계약 불일치 가능성 등)을 문서에 반영한다. 짐작으로 적지 않는다.
8. 아래 템플릿에 맞춰 섹션별 체크리스트, 불확실한 부분, 완료 후 확인사항을 작성한다. 각 작업 항목은 가능하면 관련 FR/NFR/TR ID를 인용한다.
9. 초안을 사용자에게 보여주고 확인을 받는다.
10. 확인 후 `docs/phase{N}-todo.md`로 저장한다.
11. 저장 후: 이 Phase가 마지막 Phase가 아니면 "이어서 Phase {N+1}의 todo도 작성할까요?"라고 물어 이 skill을 다시 이어간다. 마지막 Phase라면 전체 체인이 끝났음을 알린다.

## 템플릿

이 저장소의 실제 `docs/phase0-todo.md` ~ `docs/phase4-todo.md` 구조를 그대로 따른다:

```markdown
# Phase {N} TODO — {Phase 이름}

`plan.md`의 Phase {N}을 구현하기 위한 세부 작업 목록. 완료 기준: **{plan.md에 적힌 완료 기준 문장}**.

> **선행조건**(필요한 경우만): 이전 Phase 완료 상태, 현재 코드베이스에서 확인된 제약, 외부 저장소 위치 등 착수 전 알아야 할 사실.

## 1. {세부 영역 이름}

- [ ] {작업 항목} — {관련 ID가 있다면}
- [x] {이미 되어 있는 것으로 조사된 항목}

## 2. {세부 영역 이름}
...

## 불확실한 부분 (구현 착수 전 재확인 필요)

- {가정하고 있는 전제, 확인이 필요한 사항}

## 완료 후 확인사항

- [ ] `docs/plan.md` Phase {N} 완료 기준 재확인
- [ ] Phase {N+1} 착수 가능 상태인지 확인
```

## 주의사항

- 코드베이스를 실제로 확인하지 않고 체크박스를 전부 비워둔 채로 만들지 않는다 — 이미 된 것을 안 된 것처럼 적으면 다음 작업자가 중복 작업을 하게 된다.
- plan.md에 없는 작업을 이 단계에서 새로 지어내지 않는다. 계획에 없던 필요한 작업이 발견되면, 이 문서에 조용히 추가하지 말고 plan.md를 먼저 갱신할지 사용자에게 물어본다.
- 완료 후 확인사항 섹션을 빠뜨리지 않는다 — 다음 Phase로 넘어가는 관문 역할을 한다.

## 완료 후

이 skill로 체인이 끝난다(다음 문서 단계 없음). 다만 Phase가 남아있다면 위 11번대로 다음 Phase todo 작성을 제안해 체인을 이어간다.
